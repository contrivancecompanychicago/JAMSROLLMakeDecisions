# PIRDDIIQ Lab virtual medical supply chain

`PirddiiqSupplyChain.java` adds a dependency-free, in-memory Java service for modeling a basic medical-supply workflow in this repository. It is intentionally a virtual/demo implementation: data is not persisted, and this is not a validated production inventory, procurement, regulatory, or clinical system.

## Capabilities

- Catalog supplies by SKU, category, unit, and reorder threshold.
- Receive supplier lots with location, receipt date, and optional expiry date. Expiration-tracked items require an expiry date.
- View on-hand and usable quantities; expired and reserved quantities are excluded from usable stock.
- Create draft orders, reserve all lines atomically, and allocate eligible lots first-expiring-first-out (FEFO).
- Fulfill reserved orders into shipment records, or cancel draft/reserved orders and release reservations.
- Generate reorder alerts when usable quantity is at or below the configured threshold.

## Run the demo

Requires Java 8 or later. From the repository root:

```sh
javac PirddiiqSupplyChain.java
java PirddiiqSupplyChain
```

The demo registers N95 respirators, receives a sample supplier lot, reserves and fulfills an order, and prints remaining usable inventory. The class can also be instantiated from another Java program and driven through its public methods. Use `Clock` injection in tests to make dates and expiry checks deterministic.

## Typical integration sequence

1. Register each supply SKU with `addItem`.
2. Record deliveries with `receive`.
3. Create a request using `createOrder`, then call `reserveOrder` to atomically allocate stock.
4. Call `fulfillOrder` to deduct stock and produce a shipment record, or `cancelOrder` to release reservations.
5. Periodically inspect `getReorderAlerts` and `availableQuantity`.

Order IDs and shipment IDs are generated by the service. This in-memory implementation is single-process and resets on restart; connect it to an approved persistent datastore and add authentication, audit controls, and operational validation before any real-world deployment.
